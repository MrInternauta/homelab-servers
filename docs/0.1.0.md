# Release 0.1.0 — Cross-Platform Home Lab

Released 2026-08-30.

The lab now runs from the same files on **macOS and Linux**. Before this release the compose
files hardcoded macOS paths behind literal text placeholders you had to `sed` into place; they
now use real Docker Compose variable interpolation fed from per-service `.env` files, and a
single `configure.sh` sets the whole host up on either OS.

This is the first tagged release. It touches every service, both scripts, and every document.

---

## Highlights

- **One set of compose files for both operating systems.** Host paths, uids and timezone are
  variables, not baked-in strings.
- **`./configure.sh`** — detects the OS, writes every `.env`, generates every secret, creates
  every directory. One command replaces the whole manual setup dance.
- **Silent misconfiguration is now a loud error.** A missing path variable aborts the command
  with an explanation instead of mounting an empty directory over your data.
- **`DOCKER-INSTALL.md`** — installing Docker on macOS (Docker Desktop, Colima) and on Linux
  (Debian/Ubuntu, Fedora/RHEL, Arch, openSUSE), with post-install and GPU setup.
- **Linux gets its own capabilities**: GPU transcoding, GPU machine learning, real device
  discovery, USB dongle passthrough, and a Coolify that can actually deploy.

## Breaking changes

### Placeholders replaced by compose variables

The compose files no longer contain the literal text `<ROOT_USERNAME>` and `<EXTERNAL_STORAGE>`,
and the `sed`-the-repo setup step is gone along with them.

| Old                                 | New                         |
| ----------------------------------- | --------------------------- |
| `/Users/<ROOT_USERNAME>/Audio`      | `${MEDIA_ROOT}/Audio`       |
| `/Volumes/<EXTERNAL_STORAGE>/Audio` | `${EXTERNAL_STORAGE}/Audio` |
| `PUID=501` (hardcoded)              | `PUID=${PUID:-501}`         |

**`EXTERNAL_STORAGE` changed meaning: it is now a full path, not a volume name.** It was `NAS`;
it is now `/Volumes/NAS` on macOS or `/mnt/nas` on Linux. This is what makes one compose file
work on both systems.

Consequences worth knowing:

- `git status` stays clean. Machine-local values live in git-ignored `.env` files, so you no
  longer need `git update-index --skip-worktree` to hide substituted compose files.
- Path variables are declared `${VAR:?message}`. A missing value fails the command:

  ```text
  required variable MEDIA_ROOT is missing a value: set MEDIA_ROOT in .env — run ./configure.sh
  ```

  Previously Docker created a directory literally named `<ROOT_USERNAME>` and started the stack
  against empty storage — the single worst failure mode this repo had, and the one that could
  silently reinitialise Coolify's database.

### `papra-doc`: `UID`/`GID` → `PUID`/`PGID`

Renamed for consistency with the rest of the lab, and because a shell-exported `UID` could shadow
the `.env` value. `configure.sh` removes the legacy keys from an existing `papra-doc/.env`.

### Migrating an existing checkout

```bash
# 1. Discard the machine-local sed substitutions — no longer needed
git update-index --no-skip-worktree $(git ls-files '*.yml' '*.yaml') 2>/dev/null || true
git checkout -- '*.yml' '*.yaml'

# 2. Configure. Existing secrets are preserved; only missing ones are generated.
cp .env.example .env
$EDITOR .env          # MEDIA_ROOT + EXTERNAL_STORAGE — note EXTERNAL_STORAGE is now a FULL PATH
./configure.sh

# 3. Restart
./restart-all.sh
```

No data moves. The bind-mount targets resolve to exactly the paths they did before.
Full walkthrough: [SETUP.md § Migrating from the placeholder layout](../SETUP.md#migrating-from-the-placeholder-layout).

## New

### `configure.sh`

One-shot host configuration, idempotent, non-destructive:

1. Detects macOS vs Linux and your uid/gid.
2. Creates the root `.env` from `.env.example`, seeded with detected defaults.
3. Creates each service's `.env` from its `.env.example`.
4. Syncs `TZ`, `PUID`, `PGID`, `MEDIA_ROOT`, `EXTERNAL_STORAGE` from the root `.env` into every
   service that declares them — the root `.env` is the single source of truth.
5. Generates any empty secret with `openssl`. **Never overwrites a value you already set.**
6. Creates the host media directories and Coolify's state directories, and warns loudly if the
   external volume is not actually mounted.

```bash
./configure.sh              # configure everything
./configure.sh --dry-run    # show what it would do, change nothing
```

Re-run it after moving your storage.

### `DOCKER-INSTALL.md`

- **macOS**: Docker Desktop (with the Resources settings this lab needs) and Colima as a
  fully open-source alternative.
- **Linux**: Docker Engine from Docker's own repository for Debian/Ubuntu, Fedora/RHEL/Rocky/Alma,
  Arch and openSUSE — plus the required post-install steps (`docker` group,
  `systemctl enable --now docker`) that macOS never makes you think about.
- Optional extras: VAAPI drivers for Jellyfin, the NVIDIA Container Toolkit for Jellyfin and
  Immich.
- A per-OS troubleshooting table.

### Root `.env.example`

New shared configuration file: `TZ`, `PUID`, `PGID`, `MEDIA_ROOT`, `EXTERNAL_STORAGE`,
`SERVICE_HOST`, each documented with its macOS and Linux form.

### `.env.example` for every service

Was 3 (`papra-doc`, `immich-photos`, `coolify`), now **8** — added for `audiobookshelf`,
`jellyfin`, `home-assistant`, `obsidian-brain` and `portainer`.

### `COOLIFY_STORAGE`

Coolify's state directory is now its own variable rather than a hardcoded path under the NAS.
`configure.sh` defaults it to `${EXTERNAL_STORAGE}/Storage/coolify`; on Linux point it at a local
disk instead — Postgres over NFS/SMB is slow and corruption-prone.

## Linux support per service

Each is a documented, commented-out block in the service's compose file — opt in when you want it.

| Service            | Linux capability                                                                                | macOS equivalent                            |
| ------------------ | ----------------------------------------------------------------------------------------------- | ------------------------------------------- |
| **jellyfin**       | `/dev/dri` passthrough for VAAPI/QSV, plus an NVIDIA `deploy:` block and a `RENDER_GID` setting | None — CPU-only transcoding                 |
| **immich-photos**  | `-cuda` ML image tag and an NVIDIA `deploy:` block                                              | None — CPU-only ML                          |
| **home-assistant** | `network_mode: host` for working mDNS/SSDP discovery; `devices:` for Zigbee/Z-Wave dongles      | None — the VM is NAT'd off the LAN          |
| **coolify**        | Docker socket mount, so it can deploy to the host                                               | None — cannot manage the Mac                |

| **obsidian-brain** | `PUID`/`PGID` from the shared config instead of a hardcoded `1000`                              | Same fix — the old value was wrong on macOS |
| **audiobookshelf** | `user: "${PUID}:${PGID}"` so written files belong to you                                        | Same fix                                    |

## Scripts

### `restart-all.sh`

- Preflight checks: Docker installed, the compose **v2 plugin** present, the daemon reachable —
  with an OS-appropriate message when it is not.
- Skips a service that has no `.env` instead of failing mid-run with an interpolation error.
- Collects failures and prints a summary rather than aborting on the first one.
- New flags: `--no-pull` (recreate from images already on disk), `--no-test` (skip the health
  check), `--help`.
- **Exits non-zero if any stack failed** — it always exited 0 before, so nothing could gate on it.

### `test-services.sh`

- The probe target is `SERVICE_HOST` from the root `.env`, default `127.0.0.1`, overridable per
  run: `SERVICE_HOST=100.105.40.95 ./test-services.sh`. It was a hardcoded Tailscale IP, which
  made the script useless on any other machine.
- Skips the Tailscale section cleanly when Tailscale is missing or not connected, and when
  `python3` is unavailable, instead of erroring.
- Reports "cannot reach the Docker daemon" rather than dumping a raw error.
- Exits non-zero when a service is unreachable, and points at the right troubleshooting section.
- Aligned, columnar output.

## Fixes

- **`papra-doc` mounted two host paths onto `/app/app-data`**, so the repo-relative one was dead
  weight silently shadowed by the other. Known wart in the old PLAN.md; now fixed — one mount.
- **Coolify's Redis healthcheck ran `redis-cli ping` without the password**, so it could not
  actually authenticate. Now `redis-cli -a "$REDIS_PASSWORD" ping | grep -q PONG`.
- **`obsidian-brain` hardcoded `PUID=1000`/`PGID=1000`** while the rest of the lab used `501`/`20`,
  leaving vault files owned by a uid that did not exist on macOS. Now uses the shared values.
- **Container count corrected to 14** — the docs claimed 13 in one place and 15 in another.
- Removed the obsolete `version:` key from the `immich-photos` and `obsidian-brain` compose files.
- Immich's `postgres` credentials and Coolify's secrets now use `${VAR:?…}` or sensible defaults
  rather than bare `${VAR}`, so a blank `.env` fails fast instead of starting a broken container.
- `immich-photos/.gitignore` listed data directories the stack does not use (`immich-data/`,
  `postgres_data/`, `model_cache/`) and missed the ones it does (`db-data/`, `ml-cache/`).
- Root `.gitignore` gained Linux editor/desktop artefacts.

## Upgrade checklist

1. Read [Migrating an existing checkout](#migrating-an-existing-checkout) above.
2. Remember `EXTERNAL_STORAGE` is now a **full path**.
3. Mount your external storage **before** running `./restart-all.sh`.
4. 🐧 On Linux, also: `sudo usermod -aG docker $USER`, `sudo systemctl enable --now docker`, and
   allow `tailscale0` through the firewall.
